# Scenario Survey SKILL 使用指南

## 简介

scenario_survey 是一个**售前阶段**调研 SKILL，用于生成行业定制化问卷，收集客户的方案期望和需求。输出可直接输入 scenario_analyzer 进行分析的叙事文档。

**核心定位**：
- **时机**：售前阶段（方案决策前）
- **目标**：了解客户需求、期望和约束，支撑方案设计
- **语言**：默认英文；根据客户国家定制语言

**核心特点**：
- 使用客户日常语言，避免 INCOSE 等专业术语
- **问期望不问结果**：售前视角问题框架
- 引导式提问技巧，确保信息收集完整
- 行业定制化问题，针对不同行业特征设计
- 多语言支持，适配国际客户

## 使用场景

- 在执行 scenario_analyzer 分析前，需要收集客户需求素材
- 售前阶段规划客户访谈
- 需要了解客户的方案期望和成功标准
- 需要针对不同行业设计差异化问卷
- 系统性地识别所有潜在利益相关者
- 收集预期的运行使用场景细节
- 国际客户需要本地语言问卷

## 快速开始

### 1. 生成问卷

```
/scenario_survey
```

系统会询问：
- 目标行业（如 Hospitality、Healthcare、Education 等）
- 客户国家（用于语言定制，默认英文）
- 问卷模式（访谈模式或自述模式）

### 2. 执行调研

按照问卷结构进行访谈，注意使用引导技巧确保信息完整。

### 3. 合成叙事

调研完成后，将结果合成结构化叙事文档。

## 问卷结构说明

每份问卷包含八个部分：

| 部分 | 内容 | 目的 |
|------|------|------|
| 一、基本情况 | 公司介绍、项目背景 | 开场热身，建立对话 |
| 二、当前挑战 | 面临的困难、业务影响 | 确立问题起点 |
| 三、成功标准与期望 | 决策因素、优先级、成功定义 | 明确核心价值期望 |
| 四、利益相关者 | 决策者、参与者、使用者、关注者 | 确保人员全景 |
| 五、预期使用场景 | 典型工作日、不同角色用法、异常情况 | 收集预期使用细节 |
| 六、行业与环境 | 行业规定、公司规模、现有系统 | 补充背景约束 |
| 七、目标与期望 | 量化目标、成功标准、关键期望 | 确立成功定义 |
| 八、回顾与补充 | 遗漏检查、补充信息 | 完整性验证 |

## 售前问题框架要点

**核心原则**：问期望不问结果

| 错误（实施后复盘） | 正确（售前期望） |
|-------------------|-----------------|
| "之前有什么问题？" | "目前面临什么挑战？" |
| "是怎么决策的？" | "决策时会考虑哪些因素？" |
| "取得了什么效果？" | "期望看到什么效果？" |
| "现在用户怎么用？" | "用户会怎么使用这个方案？" |
| "解决了什么合规问题？" | "方案需要符合什么合规要求？" |

## 引导技巧要点

### 利益相关者完整性

**常用引导话术**：
```
"我们来从上到下梳理一下会涉及的人：
— 谁会批准这类项目？（决策层）
— 谁会负责执行和技术方案？（管理层）
— 哪些部门/团队会参与？（执行层）
— 谁会日常使用这个系统？（使用层）
— 还有谁关心结果？（关注层）"
```

### 运行场景详细化

**常用引导话术**：
```
"我们来设想方案上线后的典型工作日：
— 第一件事会做什么？
— 白天什么时候用？频率怎样？
— 高峰期有什么特殊情况？"
```

### 成功标准清晰化

**常用引导话术**：
```
"对于每个重要因素，成功是什么样子？
— 您的目标或期望是什么？
— 怎样衡量是否成功？
— 最低可接受的结果是什么？"
```

## 行业定制说明

不同行业有特定的补充问题和关注点：

| 行业 | 特定关注点 |
|------|-----------|
| 酒店/旅游 | 客人反馈、多地点统一、评分影响 |
| 医疗健康 | 数据安全、远程访问、行业合规 |
| 教育 | 学生数量、1:1政策、校园覆盖 |
| 物流 | 供应链连续性、全球运营、行业认证 |
| 零售 | 客户服务、物流效率、评分平台 |
| 制造 | 生产效率、预测维护、合规认证 |
| 体育娱乐 | 现场体验、数据洞察、高峰承载 |
| 服务行业 | 客户协作、专业效率、合规 |

## 完整性检查

调研结束后，使用检查表验证：

**利益相关者检查**：
- 决策层已确认
- 管理层已确认
- 执行层已确认
- 使用层已确认
- 外部关联方已确认
- 顾虑方已确认

**运行场景检查**：
- 触发条件已确认
- 操作步骤已确认
- 前提条件已确认
- 成功标准已确认
- 异常情况已确认

**成功标准检查**：
- 业务价值已澄清
- 当前痛点已量化
- 目标期望已设定
- 优先级已排序
- 必须达成 vs 希望达成已区分

## 与其他 SKILL 的关系

```
scenario_survey (售前收集期望)
    ↓ 输出需求叙事文档
scenario_analyzer (结构化分析)
    ↓ 输出分析报告
scenario_modeler (跨案例建模)
    ↓ 输出行业/利益相关者/购买因素模型
```
